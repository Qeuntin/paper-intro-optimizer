# paper-intro-optimizer

中文期刊论文**引言的优化与文献引用核查**技能（WorkBuddy Skill）。

它不负责"把话说漂亮"，只负责一件事：

> 引言中每个引用性论断，都有与其表述强度相匹配、可定位的证据；每项研究缺口，都能对应正文实际完成的工作。

## 它解决什么问题

中文期刊引言最常见的三种病：

1. **标签式引用**——"已有研究关注职住关系、建成环境、出行行为"，读完不知道任何一篇发现了什么；
2. **缺口硬凑**——为了凑齐"三点不足"，把方法差异说成研究空白，审稿人一查就露；
3. **表述越过证据**——只有摘要，却写需要读全文才能核实的变量口径与因果判断。

这个技能把上述问题拆成可逐条判定的检查，并要求交付时附上证据位置。

## 四项论证功能

| 功能 | 任务 | 硬性要求 |
|---|---|---|
| 背景 | 漏斗式收窄：行业趋势 → 具体现象 → 本文问题 → 为何要紧 | 必须有一句"为什么这事重要"；数据标来源 |
| 前人成果 | 按主题分 2–4 条线索，逐篇说明其论证作用 | 经验研究给"谁、对什么、得出什么"；理论/方法/测量类说明各自贡献 |
| 缺口 | 先承接已有推进，再转折指出限制 | 每项缺口有文献证据，走通"做到什么 → 何限制 → 为何影响本文 → 本文能补什么" |
| 方案与贡献 | 目的 → 做法 → 贡献 | 贡献说"提供了什么能力"，不报结果数值 |

四项功能应可辨认，**可按篇幅合段或拆段**，不要求一段只承担一种功能。

## 七条判断规则

- **R1 关联性按论证作用判断**：因变量不同的研究可用于背景、机制、方法或对照，但不得作为本文因变量的直接经验证据。
- **R2 表述强度不超过证据强度**：只有摘要，就不写需要全文才能核实的内容；经典理论、标准、政策文件无摘要也可引用，但须标明来源、阅读程度与摘要状态。
- **R3 合并引用看是否共同支持同一论断**：方法不同但结论一致可合并；结论相反不可合并。范围式编号须确认范围内每篇都支持。
- **R4 缺口须有证据门槛**：不得凭所选几篇未讨论，就断言整个领域"尚无研究"。
- **R5 贡献须可核**：能在正文找到对应分析；横截面关联不能写成因果识别。
- **R6 一处引用一个可定位位置**：摘要、全文页码、标准条款号，三者不可互相替代。
- **R7 证据取不到时**：优先补证；仍不可得则降格（须有证据支持较弱表述）、替换、移除或标"待核"。

## 证据台账

五个字段，不合并、不互相替代：

| 字段 | 取值 |
|---|---|
| 来源 | 作者原文 / 出版社或数据库 / 机构官网 / 二次转述 |
| 阅读程度 | 仅题录 / 摘要已读 / 全文相关段落已读 / 全文已读 |
| 摘要状态 | 已取得 / 原文无摘要 / 尚未取得 |
| 可追溯位置 | URL、DOI、本地路径、页码或章节 |
| 支持关系 | 引言拟写的那句话、证据原文、支持到什么程度、有什么限制 |

**题录核对、摘要阅读、全文阅读、文件下载是四件事**，任何一项都不能推出另一项。

## 交付形态

按任务规模分流，不是每次都出三件套：

| 请求 | 交付 |
|---|---|
| 优化/改写整篇引言 | 三件套：`01_引言定稿` / `02_文献摘要` / `03_文献核查` |
| 单条引用是否准确 | 单条核查卡（一处论断，一张卡） |
| 这条文献该不该留 | 删留判断卡（说明支持哪项论断，或为何建立不起关系） |
| 引言逻辑不通 | 局部结构诊断 + 问题清单 |
| 只读咨询 | 直接回答，不写文件 |

## 安装

WorkBuddy 用户级技能目录：

```bash
# macOS / Linux
git clone https://github.com/Qeuntin/paper-intro-optimizer.git \
  ~/.workbuddy/skills/paper-intro-optimizer

# Windows (PowerShell)
git clone https://github.com/Qeuntin/paper-intro-optimizer.git `
  "$env:USERPROFILE\.workbuddy\skills\paper-intro-optimizer"
```

重启 WorkBuddy 后生效。也可直接把 `paper-intro-optimizer/` 拷入项目级技能目录 `.workbuddy/skills/`。

## 触发方式

说这些话会命中：优化引言 / 改写引言 / 引言逻辑不通 / 核查文献引用 / 做文献核查表 / 这条文献该不该留 / 按引用顺序汇总摘要；或直接给一篇论文 docx 要求按"背景—前人成果—空缺—方案贡献"重排。

## 案例集的来历

`casebook.md` 的 12 条错例全部来自一次真实的引言改写：一篇中文期刊投稿稿，18 篇参考文献，五轮迭代。典型错例包括：

- 把两篇因变量完全不同的文献合并成"确认心理潜变量影响决策"——一个是政策响应，一个是短途方式选择；
- 用 `[9-10]` 合并引用，抹掉了其中一篇"三维测度"的核心贡献，与段 2 的表述自相矛盾；
- 单城市研究（深圳、南昌、周口、嘉定）的结论被写成普遍规律；
- 把"空间异质性"这句方法名当结论，"什么关系随空间位置变化"没说。

每条都记了现象、病根、改法与判断线索。

## 说明

- 本技能**不包含**字数统计与全文自动解析：那属于排版执行层，且字符数不等于期刊认定字数。
- 案例来自具体论文，其中文献事实未经外部复核，仅作为判断线索，不宜直接照搬结论。
- 技能面向中文期刊写作；英文期刊的文献体例（作者—年份制、讨论式综述）差异较大，需另作调整。
