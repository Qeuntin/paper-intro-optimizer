# 交付模板

## 交付规模先分流

| 用户诉求 | 交付物 |
|---|---|
| 优化/改写整篇引言 | 三件套 + 引用映射表 |
| 核查一条或几条引用 | 单条核查卡（下表格式），不出文件 |
| 判断某篇该不该留 | 判断卡：论证作用、证据强度、处置建议 |
| 说“这段逻辑不通” | 该段诊断 + 改法对照，不出文件 |

只有实际写入文件时才建目录、命名、归档。

---

## 共用：引用映射表

三件套共用一张表，正文若也引用同一批文献，此表是唯一权威。

| 文献标识 | 原编号 | 新编号 | 状态 | 备注 |
|---|---|---|---|---|
| **优先用 DOI**；无 DOI 用数据库记录号；两者皆无时用“作者+年份+完整题名”，并检查是否重名 | 原稿编号，无则“—”（新增） | 引言编号，未定则 `[I1]` | 保留/替换/删除/新增 | 替换写明原因 |

- 标识规则与表头一致：DOI 优先，其次数据库记录号，两者皆无时才用“作者+年份+完整题名”组合，并查重
- 未获全篇编号授权时，新编号一律用 `[I1]…[In]`，并在交付说明首行标注“**待与正文统一**”
- 删除的文献保留在表中，状态标“删除”并写明理由，便于回溯

## 文件一：引言定稿

命名：`01_引言_vNN_YYYYMMDD.md`；含未解决关键问题时改标 `_待核`

```markdown
# 引言（vNN · 目标期刊）

> 版本：vNN，YYYY-MM-DD（一句话说明本轮改了什么）
> 结构：N 段（各段承担的功能见下）
> 编号：NN 篇，编号 [1]–[NN] 按首现顺序 / 或 [I1]–[Inn] 待与正文统一
> 替换对象：原稿引言 Pxx–Pxx 共 N 段

---

（正文各段）

---

## 段落功能

| 段 | 承担功能 | 要点 |
|---|---|---|

## 四项论证功能核验

| 功能 | 要素 | 本文落点（段序或小标题） | 判定 |
|---|---|---|---|

四项功能指背景、前人成果、缺口、方案与贡献；**可在同一段内合并，也可跨段拆分**，核验的是功能是否可辨认，不是是否各占一段。判定用“成立/偏弱/缺失”，不用“通过/不通过”——结构适配是程度问题。

## 编号首现序列

`[1] → [2-3] → … → [NN]`

## 缺口—贡献对应

| 缺口及引言位置 | 证据（引文或数据） | 本文对应动作及引言位置 | 正文支撑位置 |
|---|---|---|---|

## 本轮改动

| 位置 | 原 | 改 | 理由 | 依据 |
|---|---|---|---|---|

## 待核事项

| 项 | 现状 | 需要什么才能核 | 影响 |
|---|---|---|---|

## 使用注意

- 引用标注出现在哪些章节
- 口径说明（样本、分母、扩样与否）
- 已知未闭合项
```

## 文件二：引用核查

命名：`03_引用核查_YYYYMMDD.md`

### 逐条核查（核心表）

**一行一个“论断—文献”对应关系**：同一文献支持两句话时拆两行；一句话有三篇引用时逐篇一行。否则一篇被判“直接支持”，容易掩盖它支持不了另一句话的问题。


| 文献标识 | 引言原句 | 证据原文及位置 | 表述匹配 | 证据质量/边界 | 问题类型 | 建议表述 | 处置理由 |
|---|---|---|---|---|---|---|---|
| DOI 或 作者 年份 | “……”（引号内为原文） | 摘要 / 全文 p.x / DOI | 直接支持 / 部分支持 / 不支持 / 证据不足 | 设计、样本、可外推范围及限制 | 见下 | “……” | 保留 / 改写 / 替换 / 删除，理由 |

**支持程度**四档：

- **直接支持**：证据讲的就是该论断，范围一致
- **部分支持**：方向一致但范围、强度或条件需限定
- **不支持**：证据与论断不是同一件事，或方向相反
- **证据不足，暂无法判断**：仅题录、摘要残缺、原文不可得时使用；**不得为了凑三档而强行判成“不支持”**

**两个维度分开记**（同一行内填两栏）：

- **表述匹配程度**：原文是否支持这句话（即上面四档）
- **证据质量与适用边界**：研究设计、样本、测量、可外推范围

一篇质量有限的研究，也可能直接支持一句范围明确的描述——两栏不可互相替代。

**问题类型**：主题错位 / 因变量不符 / 范围外推 / 表述过强 / 方法混淆 / 概念错位 / 编号错 / 转引未标 / 无

### 汇总

| 项 | 内容 |
|---|---|
| 论断—文献对应关系 | **共 M 条**（不等于文献篇数：一篇支持两句即 2 条，一句引三篇即 3 条） |
| 文献总数 | N 篇（保留 N / 替换 N / 删除 N / 新增 N） |
| 表述匹配分布 | 直接支持 M / 部分支持 M / 不支持 M / 证据不足 M |
| 需改写表述 | N 处，列编号 |
| 需补证 | N 处，写明需要全文哪一节 |
| 编号状态 | 已按全篇统一 / 暂用临时编号 |

### 缺口与贡献核查（若有）

| 缺口 | 支撑文献 | 是否够格（四项链） | 本文对应动作 | 正文是否有实际分析 |
|---|---|---|---|---|

## 文件三：摘要汇总

命名：`02_文献摘要_YYYYMMDD.md`

五条硬要求：
1. **原始摘要、中文翻译、分析者提炼三者分开标注**，不得把自己概括的内容标成“原文摘要”
2. 外文文献给原文，中文翻译另标“译”，提炼另标“要点”
3. 每条注明来源渠道与**阅读程度**（按实际填写：仅题录 / 摘要已读 / 全文相关段落已读 / 全文已读）
4. 每条另记**摘要状态**（已取得 / 原文无摘要 / 尚未取得）——与阅读程度是两个字段，不得互相替代。摘要尚未取得时只记“摘要归档待补”；引用是否待核，取决于已读证据能否支持对应论断
5. **原文无摘要的文献**（理论著作、标准、政策文件等）标“原文无摘要”，改列与引用论断直接相关的原文条款或段落及其位置（章节号、页码），**不得自行编写“原文摘要”**

```markdown
# 文献摘要汇总（NN 篇，按引言引用顺序）

> 编号与 `01_引言_vNN.md` 对应；映射见 `引用映射表`
> 来源、阅读程度与摘要状态逐条标注；【原文】为数据库/出版物原文，【译】为中文翻译，【要点】为分析者提炼

---

## [1] 题名

**文献标识**：与引用映射表同一标识（DOI 优先，其次数据库记录号，最后作者+年份+完整题名）
**来源**：期刊官网 / 知网 / DOI
**阅读程度**：仅题录 / 摘要已读 / 全文相关段落已读 / 全文已读（按实际填写，并注明全文可得性）
**摘要状态**：已取得（注明取自数据库/出版商页面/作者版本）
**可追溯位置**：DOI 或 URL、本地路径

**【原文】**……（逐字，不改写）

**【译】**……（仅外文文献需要）

**【要点】**……（分析者提炼，须与原文可区分）

**引用依据**：加粗的原文片段 + 对应引言原句
```

若某条只有摘要、无全文，在“阅读程度”写明，并在核查表中把涉及细节的表述降级。

若某条**原文无摘要**，卡片改为下列形式，不设【原文】摘要栏：

```markdown
## [n] 题名

**文献标识**：与引用映射表同一标识
**来源**：出版社 / 机构官网 / 标准发布机构
**阅读程度**：全文相关段落已读
**摘要状态**：原文无摘要
**可追溯位置**：文件号（如 GB/T ×××）、章节号、页码、URL

**【相关条款/段落】**……（逐字摘录与引用论断直接相关的条文或段落）

**【要点】**……（分析者提炼，须与条文原文可区分）

**引用依据**：加粗的条文片段 + 对应引言原句
```
